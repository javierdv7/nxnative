# The Legend of Zelda: Ocarina of Time

The Switch 2 base dump reaches its title screen on the Mac. VideoToolbox decodes the 1920×1080 AV1 track. The movie library runs its NDVE compute shaders to produce the background behind the logo and menu. Gameplay validation is open.

## Profile

SDK 22.2.8, NVN API 231.40, with Nintendo's sead, agl and gsys. The three loaded modules are `main`, `subsdk0` (NintendoSDK_movie), and `sdk`. The NPDM declares 48 MiB of system resources. Startup requests a 6.20 GiB heap, which fits in the profile's 12 GiB reservation with the stack and alias regions. The registered build is the supplied base dump (`v0`).

## Mac dry run

Use the rewritten `patched_v0` and the original extracted `base/romfs`. Build the host with `make -C dm/host GAME=0400486024DEC000` and use the [Mac shader build](../../../docs/development.md#build-by-hand-mac). From the repository, set `DUMP` to the folder containing `base` and `WORK` to the build and run workspace beside it.

```sh
mkdir -p "$WORK/run/save" "$WORK/run/temp" "$WORK/font"
python3 dm/tools/make_ext_font.py "$WORK/font/nintendo_ext.ttf"
DM_ROOT="$WORK" DM_ROMFS="$DUMP/base/romfs" DM_SAVE="$WORK/run/save" \
  DM_TEMP="$WORK/run/temp" DM_MSL_DIR="$WORK/shader/cache" DM_FONT_DIR="$WORK/font" \
  DM_NVN_SHMAP="$PWD/dm/games/0400486024DEC000/shader_map.tsv" \
  DM_WINDOW=1 DM_METAL_HUD=1 DM_FOCUS_KEEP=1 DM_AUDIO=1 \
  dm/host/dmhost "$WORK/patched_v0"
```

`DM_FOCUS_KEEP=1` lets the title keep playing while another app has focus. The profile prewarms the 11 NDVE compute pipelines used by the title. On the Apple M5 that took 17.7 s on a cold run, with a progress screen, and 7 ms with the archive warm. Compiling the same pipelines during the first submission had blocked the first movie frame for tens of seconds. The larger scene shader set also triggers a separate graphics-pipeline prebuild. On the first run with that set, the startup screen took 86.9 s to hand out all pairs, and the remaining workers finished after 110.6 s total.

Start a new game to reproduce the opening scene transition. With the test save and title flow, `DM_KEYS=f2600:A,f2950:A` advances the menu automatically. `DM_NVN_SHDUMP` saves control sections and code for missing keys to the directory it names.

For a run past the opening, copy the committed save folder to the new run's `DM_SAVE` and load slot 00 from the menu. The checkpoint contains both `slot_00/progress.sav` and `slot_00/caption.sav`. The load screen identifies it as **Kokiri Forest Autosave**. A windowed reload reached the playable scene with the HUD and controls, so rendering can be tested without replaying the movie.

## Found on this game

- The online library's [eventfd for its poller](../../../docs/reference/services.md#eventfds-served-offline) and the [virtual audio input list](../../../docs/reference/audio.md#no-virtual-audio-input-devices-sdk-22) blocked startup.
- The SDK's [NDVE pack](../../../docs/reference/shaders.md#the-movie-librarys-ndve-shader-pack) contains 22 compute programs. The title route uses 11.
- The [raw write log and pool lookup](../../../docs/reference/frame-rate.md#a-full-frame-shader-overflows-the-raw-write-log) took the windowed title movie from a 47.6 ms median to 16.67 ms on an Apple M5, at 1920×1080 decode. A steady 300-frame window averaged 60.0 fps and its GPU median was 15.94 ms. A simultaneous ten-worker shader build caused additional stalls. The same run returned to 60.0 fps when the build paused.
- A [play report send](../../../docs/reference/services.md#an-asynchronous-play-report-opens-prepou) aborted at the first gameplay transition after a failed `prepo:u` connection. A Mac dry run with the offline completion finished the 9,254-picture opening movie and continued submitting the live scene. The title-only shader set left the scene black.
- The white 3D scene was agl's [conditional depth clears](../../../docs/reference/rendering.md#conditional-rendering-evaluated-at-replay) run unconditionally (resolved; the profile sets `render_cond on`). The main opaque pass tests `EQUAL` against a copy of the prepass depth that agl clears under a condition right after copying, a clear the console skips. Without the key the copy was 1.0, no lit geometry passed, and the full-screen sky (`943d8c0ece545cc8`) showed through. With the key the saved Kokiri Forest scene renders: Link, the ground, the props, lighting and the HUD.
- Mesh-shaded models were missing, among them the door of Link's house: the split read six stage slots of each BNSH program, and NVN2 keeps [task and mesh shaders in slots 7 and 8](../../../docs/reference/shaders.md#task-and-mesh-shaders-in-nvn2-bnsh-program-slots-7-and-8) (resolved). The new split adds 491 mesh and 17 task shaders to the map, 53 of the 54 keys the Kokiri Forest scene had asked for. 511 of their 520 build; the door renders.
- Kokiri Forest ran at about 20 fps with the GPU two-thirds idle: the [bindless pool table was rebuilt for every registration](../../../docs/reference/frame-rate.md#a-bindless-pool-table-rebuilt-for-every-registration), and about 12,000 descriptors of finalized texture objects churned the ghost ring (resolved). The frame is now 16–21 ms at the median on an Apple M5, submit 5–8 ms, and the GPU (14–21 ms) is the limit.
- The first 3D scene exhausted Metal memory when [bindless pool walks churned finalized textures](../../../docs/reference/nvn-objects.md#a-bindless-pool-churns-finalized-textures-within-a-submission). On the Apple M5, the failing run reached 18,930 MiB of residency. With submission-local backing, residency was 7,946 MiB about ten seconds after the movie and 7,871 MiB at 35 seconds. The opening 3D scene and its subtitles presented, and the test host exited normally.
- The 1.1.1 update froze for good about 13 minutes in, at the save after the Deku Tree cinematic: the [raw global memory pool table was too small for the game's pools](../../../docs/reference/shaders.md#a-raw-global-memory-pool-table-too-small-for-the-games-pools), 4,118 against 4,095 entries, and the next submission hung the GPU (upstream issue #1326 reports the same freeze with 4,248 pools). The hung shaders are agl's task shaders `99280b7b8aae78df` and `47f9b38490dcf9a2` ([lunks, from `DM_NVN_HANGLOG`](https://github.com/seedds/nxnative/issues/1326#issuecomment-6664549683)): they read both ends of a range through raw loads, and with both read as 0 they loop 2^27 − 1 times, so reading 0 for an address left out is no safe fallback for them. The table now grows with the pools (lunks' design, `574a38f0`); on the Apple M4 (16 GB), chain `cd1da67c132d`, a run past that save grew it to 8,192 entries for 4,109 ranges with no overflow line and no GPU hang, both task shaders running (resolved).
- In Kokiri Forest the foliage moved frantically. Six foliage compute shaders (`FoliageShader.sharcb`, `13002657609092b4` and five others) stopped at Ampere opcode `0x3a9`, [ATOMG.CAS](../../../docs/reference/shaders.md#atomgcas-a-global-compare-and-swap), and were left out; they translate now, and the shader build of chain `cd1da67c132d` built 42,853 of 42,854 shaders, the one left being `68bbe98b3bfd9876`, data in place of code. Whether they were the frantic foliage is not checked yet (open).
- Two agl_technique_pfx compute shaders (`1f78730053feb036`, `e172bd7ec218ab8e`) did not compile: [blocks nested past clang's bracket depth](../../../docs/reference/shaders.md#blocks-nested-past-clangs-bracket-depth), 257 levels from an unrolled 256-element walk (resolved by the compile flag; the nesting itself is open).
- 34 shaders dropped their [float atomic adds](../../../docs/reference/shaders.md#float-add-atomics) (`RED.F32.FTZ.RN`, `Invalid reduction type: F32FtzRn`); they are a compare-and-swap loop now (lunks' #1359, resolved in the translator; it had left the outdoor scenes washed out; checked in the next run).
- The first launch with shader libraries [looked hung before its first picture](../../../docs/reference/services.md#a-game-paused-out-of-focus-looks-hung-before-its-first-picture): the window had lost key status while the progress screen compiled the 11 NDVE pipelines (72 s on a cold Metal cache), and the game, in focus handling mode 2, pauses out of focus. It went on at `oe focus state → 1` (resolved: the Mac window now says the game is paused).
- The CPU-side freezes in Kokiri Forest (frames of 0.2 to 2 s of `submit+present` with no new pipeline) were [patched pool tables churning the residency set](../../../docs/reference/frame-rate.md#patched-pool-tables-churn-the-residency-set): 600 to 900 table buffers added and removed per 300 frames (resolved: retired tables are reused). Measured on an Apple M4 (16 GB), chain `cd1da67c132d`, `DM_PSO_PREBUILD=0` with the same warmed pipeline archive in both runs, the same save and route (standing, then walking), Spotlight and Time Machine paused; from frame 2100, the scene loaded, to the memory wall below: before, frame time p50 30.4–31.1 / p95 214–231 / max 484–747 ms, `submit+present` p50 4.8–5.0 / p95 10.9–16.8 / max 371–590 ms, 606 residency commits and 611 buffers added and removed per 300 frames, 104 frames with more than 100 ms of `submit+present` and no new pipeline (54.5 s); after, frame time p50 27.3–30.1 / p95 32.8–36.3 / max 34–144 ms, `submit+present` p50 3.9–5.4 / p95 5.9–9.6 / max 8–29 ms, 12–53 commits and no pool-table buffer added, none of those frames.
- Walking the forest made GPU memory climb in bursts: [retired texture IDs were re-created over storage another texture took](../../../docs/reference/nvn-objects.md#retired-texture-ids-re-created-over-storage-another-texture-took), zero-filled textures nothing drew (aCidcOde, upstream issue #1326; resolved in the host). Measured on an Apple M4 (16 GB), chain `cd1da67c132d`, the B-2 route (save `save_kokiri`, 75 s standing, a 120 s walk), Spotlight and Time Machine paused, one run each: before, the walk drew 314 frames, frame time p50 86 / p95 1,646 / max 8,388 ms, and ended in a GPU out-of-memory error (11,775 MB allocated against Metal's 12,124 MB working set) and a command buffer error; after, two runs drew 1,325 and 3,096 frames, p50 66 and 32 / p95 279 and 74 / max 1,187 and 3,840 ms (the second run's slowest frames are two pass dumps another session asked for), with no GPU error, GPU allocated 10.7–11.1 GB. The two runs after differ widely, so the timing is noisy; the memory line's counts are not: 5,190 private textures made by the end of the walk, all for live texture objects, none for retired IDs (1.25 million retired-ID lookups read as empty slots).
- After a GPU out-of-memory error the Mac froze hard (owner's run, frame 9,695; aCidcOde's kernel log: the kernel failing to wire memory for minutes): the host now [stops at Metal's working set](../../../docs/reference/memory.md#past-metals-working-set-the-kernel-fails-to-wire-memory-and-the-mac-freezes), exit status 3 (a guard; whether it is early enough on every Mac is open).

- The game played slow whenever a frame took longer than 16.7 ms: it turns its own frame-rate controller off and fixes the present interval at 1 (`main+0x33723d0`), and its updates are once a frame. A frame step stub at the framework's interval setter `main+0x346c5c0` (this profile's `patches.py`, build `e0f3ccfa…`, `fps_target 60`) hands the game the host's step. With holds up to 3 vsyncs Kokiri Forest ran at 0.709 of real time on an Apple M4; past 3 vsyncs the time was lost, [Frames longer than three vsyncs lose game time](../../../docs/reference/frame-rate.md#frames-longer-than-three-vsyncs-lose-game-time) (`fps_hold_max 4`). Open: the field the logic reads for its time step was not found; the speed was judged by eye and by the host's game-time ratio.
- Most indirect quad and 8-bit-index draws split their render pass: [Indirect draw conversions made stale by every buffer write](../../../docs/reference/rendering.md#indirect-draw-conversions-made-stale-by-every-buffer-write) (partly resolved: 85% → 65% of conversions split).

## Mac (Apple M4, 24 GB): state and measurements

Run from the update-only NUP (v131072) with `DM_OPMODE=0` (handheld, 1920×1080 output), `DM_UPSCALER=metalfx`, `DM_NVN_NDVE_MOVIE_DIRECT=1`, `DM_NVN_GPU_TS=segment`. Goal: a steady 40 fps at 1080p.

- Movies: 60 fps, in sync, with the direct NDVE scale (the NDVE network took 100–160 ms of GPU a frame on this GPU).
- Kokiri Forest: 15–30 fps. GPU busy 20–37 ms a frame (handheld and docked alike: the cost does not follow the resolution, and the game's dynamic resolution falls to 683×384 / 854×480); the CPU's translation 13–18 ms a frame (about 156,000 instructions a draw, 1,250 draws); GPU idle gaps of up to 15 ms waiting for submissions. One 854×480 pass of terrain, a leaf effect and about 11 full-screen draws takes 6–11 ms twice a frame; the frame's compute (foliage, effects) about 7 ms, spread over many dispatches.
- Memory: footprint 14–17 GB in the forest. With other apps open the Mac swapped 11–12 GB, which made the pipeline prepare step take 21 s instead of 0.5 s and slowed frames.
- Pipelines: with the archive warm, a revisited area compiles nothing (0 bases, 0 stand-in draws in a 5-minute walk); a new area still compiles on the spot and draws with stand-ins meanwhile (white or missing foliage, open).

## Open
- The memory wall below ended the owner's run past the Deku Tree save (chain `cd1da67c132d`, 470 s in, a minute after the pool table grew): `Insufficient Memory (kIOGPUCommandBufferCallbackErrorOutOfMemory)` with the residency set at 11,802 MB against Metal's recommended working set of 12,124 MB, the process 15.6 GB resident. Its largest item is the 2.4 GB alias region (`mem_alias 0x98000000`), which the raw global memory pool table wires whole. No frame came after it and the Mac froze until a hard reboot. aCidcOde ([issue #1326](https://github.com/seedds/nxnative/issues/1326#issuecomment-6667424114)) traced such bursts to registered descriptors of finalized textures re-created as zero-filled textures on whole pool table builds, and the unkillable freeze to the GPU scheduler failing to wire memory. Open (B-6).

- Link's house door draws neon white (the owner, the same run). Not diagnosed: a frame capture of the door (`DM_NVN_PASSDUMP`) is the next step.

- (Partly resolved: the bursts were [retired texture IDs re-created](../../../docs/reference/nvn-objects.md#retired-texture-ids-re-created-over-storage-another-texture-took); still open: GPU allocated stays at 10.7–11.1 GB of Metal's 12.1 GB, with 5.5 GB of memory-pool buffers resident, 2.4 GB of them the one large pool the raw global memory table wires whole.) On a 16 GB Mac (Apple M4) the forest outgrows memory as the player walks: the residency set holds 10–11 GB, and once a walk adds about 700 MB of textures the GPU takes 1.4 to 7.6 s a frame (paging), and one run ended in a command buffer execution error (`MTL4CommandQueueErrorDomain` 1, frame 2973). Seen alike with and without the pool-table fix. Open: what holds that much (`DM_CTL restop` lists the largest resources).

- The opening cinematic's sound drops out (the owner heard it stop when the castle gate opens and come back after Ganondorf rides past). Measured with `DM_AUDREN_TRACE=1 DM_MOVIE_TRACE=1` on the Mac (session B of OoT1, three runs): stretches of exact digital silence of 0.3 to 37 s every 10 to 30 s through the 9,254-picture movie, at different places in every run. The sound is not the movie's: the movie module decodes only AAC, and `main` plays the cinematic's sound as its own Opus streams through `DecodeOpusInterleavedWithHardware` (one call site, `main+0x36d4b10`, a wrapper reached through a vtable in the game's audio engine). The AV1 decoder runs steadily through the silences (about 31 pictures and 3 to 4 refused packets a second), and so do the frames (as many long frames in silent seconds as in the others). In each silence the game makes no Opus decode call at all, and the thread dumps taken there show every thread waiting for work (`OpusDecoder` on its address wait, the audio framework threads idle), none on a file or a lock. So the game's audio engine stops asking for the stream: why is open. Next: find what pauses or stops those streams (the engine's voice or stream state around `main+0x36d4b10`, and whether it follows the movie's playback position).

- Of the task and mesh shaders, nine do not translate: eight foliage shaders stop at Ampere opcode `0x243` (packed conversion, source A `RZ`, mode `0x0000c4ff`; three of them, `604134a5262ff670`, `ecead5cd0569091f` and `fed302d791a4ba43`, are drawn in Kokiri Forest), and one at ISBERD mode `0xb8` in a task or mesh shader. The scene also asks for `d17eefaff4f0bc23`, whose code is in none of the shader archives.
- The title-only build logged 3,331 distinct mapped libraries it could not open, including 363 shaders that failed when setting up programs. A targeted build for those programs and their dependencies translated 6,132 of 6,134 shaders. The two failures are foliage compute shaders `8692b34b521225be` and `83df46a0b1b379b4`, both with Ampere opcode `0x243`.
- With `render_cond` on and the shader build still incomplete, Kokiri Forest showed a hard horizontal cut, sky colour above the horizon over the trees. The volumetric fog composite (`888c1068ac8f7043`, agl) takes a pixel whose R32Float depth copy reads above 0.9999 as sky and paints the sky lookup there. The pass that fills that copy draws with agl's full-screen vertex shader `fb1ed54be1baced1`, which that build had not reached yet, so the host skipped the draw (`draw skipped: no render pipeline`) and dropped the target's store. Retest with the stamped full build. The sky lookup's peaks (about 105, 67 and 36 in RGB) are unverified against the console.
- The opening scene calls `nvnCommandBufferDrawMeshTasksIndirect`, which the host does not implement. On `v0` the probe caught the return at `main+0x2be2dc0`; the branch builds the command buffer pointer in `x0` and the indirect argument address in `x1`. It does not set `x2` on that path. A separate sample of the first 64 bytes at the indirect address returned zeros after the call; the populated record's layout is still unverified. The title-only run logged 11 keys missing from the map. The expanded run captured seven of them before the memory failure. A byte-for-byte comparison found none of those seven code areas in the extracted shader package.
- The 3D scene's CPU cost (37–59 ms a frame, with pool walks of about 33,000 descriptors) is [resolved](../../../docs/reference/frame-rate.md#a-bindless-pool-table-rebuilt-for-every-registration). Open: the GPU's 14–21 ms a frame in Kokiri Forest, which still drops frames below 60 fps; TBDR optimizations are off for this bindless game (`DM_NVN_TBDR=1` turns them on), and attachments load and store about 330 MB a frame.
- The Nov. 4 Lichii branches offer two shader leads. Its [packed conversion lowering](https://github.com/zortos293/Lichii/commit/35c043b3efaa147d1c1afe8a52cdf19fa92b77bf) handles opcode `0x243` with source A set to `RZ` and mode `0x0000c4ff`; both of this game's failed foliage programs use two registers and mode `0x000004ff`, which needs independent verification. Its [floating-point global reduction](https://github.com/zortos293/Lichii/commit/3aa89d1cdbe58a2bd5ded06b9c615c78da2ade70) matches the `F32FtzRn` diagnostic of the Mac shader build, now [resolved here](../../../docs/reference/shaders.md#float-add-atomics). Neither of the two shaders in the sky lookup and draw uses those instructions or the gather opcodes from Lichii's [fog work](https://github.com/zortos293/Lichii/commit/375c4a472bd95fdfaae0de6e3f192499cd14f806).
